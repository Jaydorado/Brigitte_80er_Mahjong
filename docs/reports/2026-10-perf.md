## Feedback round 1 — level 8, commit `06d0a13`

Commit measured: `06d0a13` (`main`, the final tree of feedback round 1: eight levels, layer shading, riddle answer and photo). Result: **all six budget items pass** on level 8, headless and headed. The warm pre-baked level start, the number of record, is **65 ms headless and 67 ms headed** (budget ≤ 400 ms).

Setup as in the original protocol below (Chromium 145.0.7632.6, 800×360, DPR 3, mobile with touch, 4× CPU, warm service worker, real touch taps, median of 3 runs per series), with these changes from spec §Testing → Perf:
- The level under test is **level 8** (`eighty`, 96 tiles, 4 depths) instead of level 6.
- **Largest atlas.** A cold bake of every level's atlas (`atlas-scan`, headless) ties levels 6, 7 and 8 at 1339×1364 px (1.826 Mpx); their cold bakes take 421, 450 and 474 ms. Level 8 is both the largest and the slowest bake, so it covers both scenarios. Levels 1–5 bake between 0.75 and 1.36 Mpx.
- Four level-start paths, each measured on its own:
  - **warm start:** the map has pre-baked level 8 in idle time and the pre-bake has decoded before the tap;
  - **tap early:** the tap lands before the pre-bake has finished, and the level takes over the unfinished bake;
  - **replay, uncached:** a fresh page with every level won, then a tap on won candle 8, whose atlas is in no cache and is not baking;
  - **resize rebake:** level 8 is up, then the viewport goes from 800×360 to 720×330; the tile width changes and a new atlas replaces the board.

|---|---|---|---|

- **Off-path starts are over 400 ms.** Both paths bake the whole level-8 atlas on the tap, so they cost a full bake plus the level mount. The budget line and spec §Testing name the warm pre-baked start as the number of record. These two paths were measured, not optimised. A player meets them by tapping candle 8 within about 0.6–0.7 s of the map appearing (the pre-bake's length, idle waits included: 570 ms headless, 654 ms headed), or by replaying a won level whose atlas is not cached, e.g. after the app was reloaded. Levels 6 and 7 share level 8's atlas size, so their off-path starts cost about the same; levels 1–5 bake smaller atlases. In the headed tap-early series the pre-bake had not started at the tap in two runs out of three, so those were from-scratch bakes.
- **Pre-bake on the map.** The level-8 pre-bake takes 570 ms headless and 654 ms headed, idle waits included, and runs only in idle periods.
- **Resize.** The rebake holds one 68–71 ms task. Its longest dropped-frame run is 66–67 ms (budget 100 ms). A resize is not a tap/match window.
- **Level-start task.** As before, the warm level-start window holds one task of 65–74 ms: the tap's click task (level mount, first style and layout, backdrop SVG).

## Original protocol — level 6, commit `0723e0c`

Commit measured: `0723e0c` (`main`). Result: **all six budget items pass**, both headless and headed.

### Setup

- **Chrome:** Chromium 145.0.7632.6 (Playwright 1.58 build). Two series: the headless shell and the full headed browser.
- **Emulation:** 800×360 viewport, DPR 3, mobile with touch. CPU throttled 4× through CDP `Emulation.setCPUThrottlingRate`.
- **Warm start:** the first load installs the service worker and waits for `activated`; the throttle is then set and the page reloaded. A run aborts if `navigator.serviceWorker.controller` is not set on the second load.
- **Build:** the production build with `VITE_BASE=/`, served by `vite preview`. The smoke flag `VITE_SMOKE=1` exposes a test hook, but only with `?smoke`.
- **Input:** every tap goes through `page.touchscreen.tap`, which sends real CDP touch events.
- **Scenario:**
  - Enter level 6 with a real tap on candle 6.
  - Make 5 matches, then 1 *Zurück* (undo), then 1 *Mischen* (shuffle).
  - Leave the level and replay level 1. The first 16 of its 18 pairs are fast-forwarded through the test hook and not measured. The last two pairs are real taps; the last one wins, and the confetti follows.
- **Method:** each run is one invocation of the harness. The reported value is the median of 3 runs per series.

### Results (median of 3)

| Budget item | Budget | Headless | Headed |
|---|---|---|---|
| Level start, level 6 (candle tap → first frame with every tile painted) | ≤ 400 ms | **65 ms** (65 / 66 / 65) | **66 ms** (68 / 66 / 64) |
| Match animation fps (5 matches pooled) | ≥ 55 | 60 | 74.4 |
| Confetti fps | ≥ 55 | 60 | 74.8 |
| Worst dropped-frame run (all animated windows) | ≤ 100 ms | 0 ms | 26.7 ms |
| Long tasks > 50 ms, tap → selection or match | none | none | none |
| Resting level-6 compositor layers (no selection or hint) | ≤ 12 | 6 | 8 |

Headed fps equals this machine's display rate (74.8 Hz). The headless frame clock is a fixed 60 Hz timer.

**Level-start task.** The level-start window holds one long task of 65–69 ms. It is the tap's click task itself: mounting the level screen, its first style and layout, and parsing the backdrop SVG. It lies outside the tap → selection/match windows the long-task budget counts.

#### History of the level start

| Commit | Headless median | Headed median | Change |
|---|---|---|---|
| `2df52b9` | 581 ms | 585 ms (1 run) | Baseline. The atlas was baked from scratch on the tap. |
| `d84e0cc` | 194 ms | 313 ms (1 run) | The map pre-bakes the current candle's atlas in idle time. Atlases are cached by tile width, DPR, and face set. The clue fit uses a binary search. |
| `7afc6d0` | 180 ms | 413 ms | Headed miss: at 75 Hz the idle periods (8–10 ms) never met the old 10 ms gate, so the bake still ran on the tap. |
| `0723e0c` | 65 ms | 66 ms | Idle steps are admitted against their measured cost. Each tile is drawn as a body pass and a face pass, with pixels identical to before. The pre-bake pauses while the page is hidden and recovers from starvation. |

Spec §Performance item 1 says the atlas is rendered "at level start". It is still the same atlas: same resolution (`min(DPR, 3)`), same cells, same pixels. It is now usually rendered on the map, just before the tap. If a player taps before the pre-bake finishes, the level takes over the unfinished work at no more than the old cost.

Pre-bake cost on the map, headed at 4× CPU, measured by the builder in `0723e0c` (355 idle steps in a 5-run trace):
- No step ran past its idle deadline.
- Steps take 3–4 ms each (p50 3.0 ms in the round-4 trace).
- The largest atlas allocation, 10.4 Mpx, takes 20.0 ms.

## Limits (both rounds)

- **Headless shell.** It rasterises in software (SwiftShader) on a fixed 60 Hz clock, so fps cannot exceed 60. It still catches stalls: a 150 ms busy task injected by the harness self-test shows up as a 150 ms long task and a 133 ms dropped-frame run.
- **Headed browser.** It uses this machine's GPU and display, and its fps varies with other desktop load. The layer count that matches the DevTools Layers panel is the headed one (8). Headless reports 6.
- **CPU throttling.** It slows only the main thread. It models neither a phone GPU, nor its memory bandwidth, nor thermal limits. **The physical Android phone check stays mandatory.**
- **Warmer second mount.** The level under test is mounted a second time through the test hook, after the measured level start, so that the harness can track the board. That second mount is warmer, so it is used only for the matches and the layer count.
- **Where the marks sit.** `level-start` runs from the candle's `click` handler to the first rAF after the board is in the DOM. Touch → click dispatch is not included.
- **120 Hz phones.** Their idle periods may be shorter than the 6 ms minimum step. The pre-bake then waits, or the level takes it over (the old from-scratch cost). This path was not measured on a phone.
- **Very large screens.** A starved pre-bake step can admit the atlas allocation early. On a very large screen at DPR 3 that allocation is unbounded and could exceed 50 ms on the map. It stays outside the tap/match windows. Accepted as ruling R29.
